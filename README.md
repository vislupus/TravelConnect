# TravelConnect

Всеки ден (два пъти) проверява страниците на пътуванията от **cedadventures.com**,
които си описал в `travels.yaml`, записва всички дати, цени, свободни места и
бележки за „възможност за комбинация“ в SQLite и праща съобщение в Slack, когато
на някоя дата се появи човек, с когото да споделиш стая. Всичко се вижда на една
страница в GitHub Pages.

Работи изцяло в GitHub Actions – не трябва да пускаш нищо от компютъра си.

## Какво прави

1. **`travels.yaml`** – списъкът с линкове и настройките (кого търсиш за стая и за кое да те известява).
2. **Проверка** (`python -m tracker`, в 08:30 и 18:30 българско време):
   - отваря всяка страница и чете секцията „Дати на програмата“ – за всяка дата:
     период, вариант на програмата (напр. „ЯПОНИЯ САКУРА“), цена, бутон
     („ЗАПИШИ СЕ“ / „РЕЗЕРВИ“), брой свободни места, бадж („НОВА ГРУПА“,
     „ПОТВЪРДЕНА ГРУПА“) и бележката „(възможност за комбинация с мъж/жена)“;
   - записва снимка на всяка дата в `data/travels.db` и я сравнява с предишната;
   - разликите стават **събития**: нова дата, промяна в цената, появила се /
     изчезнала комбинация, промяна в местата, пълна група, отново има места,
     потвърдена група, свалена дата;
   - по събитията праща Slack съобщения (виж по-долу);
   - пресмята `data/summary.json` за сайта, записва двата файла в git и публикува сайта.
3. **Сайтът** (`docs/index.html`) показва най-отгоре това, което те интересува –
   датите с възможност за комбинация и бутон „ЗАПИШИ СЕ“ – после всички дати и
   цени по пътувания (с история на цената и местата за всяка дата) и дневник на
   промените.

## Известия в Slack – кога и колко

Правилото е **само първия път**. Съобщение идва при *промяна* спрямо предишната
проверка, не всеки ден, докато състоянието е същото. Ако комбинацията изчезне и
след месец се появи пак, това е нова възможност и идва ново съобщение.

| Съобщение | Кога |
|---|---|
| 🧔 **Има мъж за комбиниране** (отделно, с бутон „ЗАПИШИ СЕ“) | на дата се появи „възможност за комбинация с мъж“ – или „възможност за комбинация“ без посочен пол, защото може да е и мъж. Праща се и при първата проверка на ново пътуване. |
| 📋 **Промени по пътуванията** (едно общо съобщение на проверка) | нова дата, променена цена, остават ≤ 2 места, пълна дата отново има места, комбинацията с мъж вече я няма |
| ⚠️ Грешки | някой линк не може да бъде прочетен |

Първата проверка на ново пътуване не праща „нова дата“ за всичките му дати – само
комбинациите, ако има такива.

В `settings` можеш да смениш пола (`combination: жена` или `any`), да включиш
известие и за другия пол (`notify_any_combination`), да изключиш отделни видове
новини (`notify_new_dates`, `notify_price_changes`, `notify_last_seats`,
`notify_available_again`) или да получаваш ежедневно напомняне, докато има
комбинация (`repeat_alerts_daily: true`).

## Настройка

### 1. Пътувания – `travels.yaml`

```yaml
settings:
  combination: мъж          # кого търсиш за стая: мъж | жена | any
  notify_last_seats: 2      # известие, когато остават <= 2 места

travels:
  - https://cedadventures.com/travels/yaponia/
  - url: https://cedadventures.com/travels/yuar-namibiya/
    name: Намибия           # (по избор) кратко име за сайта и Slack
```

Промениш ли файла в `main`, проверката тръгва веднага. Пълното описание на
настройките е в коментарите на файла.

### 2. GitHub Pages

Settings → Pages → Build and deployment → Source: **GitHub Actions**. Сайтът ще е на
`https://<потребител>.github.io/<хранилище>/`. Линкът към него се слага и в Slack
съобщенията (променлива `DASHBOARD_URL`, ако сайтът е на друг адрес).

### 3. Slack

Settings → Secrets and variables → Actions → **Secrets**. Или бот, или webhook:

| Secret | Какво е |
|---|---|
| `SLACK_BOT_TOKEN` + `SLACK_CHANNEL_ID` | Bot User OAuth Token (`xoxb-…`) на Slack приложение с права `chat:write`, поканено в канала, и ID-то на канала |
| `SLACK_WEBHOOK_URL` | Incoming webhook (`https://hooks.slack.com/services/…`) |

Без тях всичко работи, само известията се пропускат (пишат се в лога на Actions).

### 4. Първа проверка

Actions → **Проверка на пътуванията** → Run workflow (или просто промени
`travels.yaml`). Тя създава `data/travels.db` и `data/summary.json` и публикува сайта.

### 5. Ако сайтът блокира GitHub

Проверката може да върви от твоя компютър със self-hosted runner:

1. Settings → Actions → Runners → New self-hosted runner, следвай стъпките.
2. Settings → Secrets and variables → Actions → **Variables** → `RUNNER` = `self-hosted`.

## Какво показва сайтът

- **Най-отгоре** – датите с възможност за комбинация с този, когото търсиш
  (зелени карти с дати, цена, места, откога стои бележката и бутон „ЗАПИШИ СЕ“,
  който води право към формата за резервация). Под тях – комбинации с другия пол,
  последни места, нови дати и промени в цените през седмицата. Ако няма нищо –
  пише го ясно.
- **Всички дати и цени** – по пътувания: период и дължина, вариант, цена и как се
  е движила (▼/▲ спрямо първата проверка, или „без промяна (N проверки)“), места,
  комбинация, откога се следи. Натискаш ред → графика на цената и какво е пишело
  на сайта във всеки период. Отметката „минали и свалени дати“ показва и
  историята.
- **Какво се промени** – дневникът на събитията с филтри; маркирани са тези,
  за които е пратен Slack.

## Локално

```bash
uv sync
uv run python -m tracker --dry-run      # само показва какво вижда, без запис
uv run python -m tracker --no-notify    # записва в data/, без Slack
uv run pytest                            # тестове върху записани страници
```

За да видиш сайта локално: копирай `data/summary.json` в `docs/data/` и пусни
`python -m http.server` в папката `docs`.

## Структура

```
travels.yaml            списък и настройки
tracker/
  config.py             четене на YAML
  fetch.py              изтегляне (requests, резервно curl_cffi)
  parser.py             четене на страницата – дати, цени, места, комбинации
  changes.py            какво се е променило и кое заслужава известие
  notify.py             Slack съобщения
  db.py                 SQLite схема (travels, departures, snapshots, events, runs)
  export.py             data/summary.json за сайта
  main.py               проверката
docs/index.html         сайтът
data/travels.db         базата (пише се от Actions)
tests/                  тестове + записани страници във fixtures/
```
